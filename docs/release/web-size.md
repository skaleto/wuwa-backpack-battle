# Web 无损减包记录（2026-10-30）

基线为 GitHub `v0.1.0-demo.1` Web 导出，玩法 V138。优化仅改变 Web 资源包装和缓存读取，未调整游戏规则、物品、商店、画面分辨率、音频或在线池身份。当前优化包在本地，尚未替换 GitHub Release。

## 体积口径

| 指标 | 原始字节 | 优化字节 | 减少 |
| --- | ---: | ---: | ---: |
| PCK | 1,069,805,124 | 577,362,124 | 46.03% |
| 全部 `index.*` Web 文件 | 1,109,654,506 | 617,211,505 | 44.38% |
| 部署 ZIP | 867,124,507 | 约 519,300,000 | 约 40.1% |

Web 文件总量约从 1,058 MiB 降至 589 MiB，减少 470 MiB。它比 ZIP 更接近未启用 HTTP 内容压缩时的冷启动下载预算；不把 ZIP 体积当作浏览器流量，不宣称下载时间按同比例缩短。ZIP 精确字节和 SHA-256 以构建报告为准（随附说明更新也会改变归档字节）。

## 实现

1. `RuntimeSourceBytes` 在 Web 导出时保留直接解码的原图，跳过这些图像的重复 `.ctex` 和导入映射；字体及音频等仍按原方式导出。导入资源从约 330 MiB 降至 17 MiB。桌面导出分支不变。
2. 255 个离线轮廓缓存只在独立暂存目录中用 Godot Zstandard 压缩，从 212,473,372 降至 48,236,296 字节。逐文件解压后 SHA/字节与来源相同，坐标、采样点和四方向数据不重算。
3. `ArtGeometry.read_cache` 识别 Godot 压缩文件头，也继续接受原始缓存。原有描述符内存缓存仍在，未把解压放入逐帧绘制循环。

未进行有损图像压缩、缩分辨率、删角色/物品/音乐、修改兼容目录或冻结回放。完整 Web 包依然大于常见免费 Pages 的单文件限制，这轮不包含分包加载与在线托管部署。

## 验证与证据

- 构建日志：`build/web-optimization/web-logs/`。
- 包内检查：从独立空目录挂载 PCK，486 份原始资源字节校验通过，405 张图片解码通过，255 份压缩缓存解压与解析通过；未回退读取源码目录。
- 浏览器：隐藏 Chromium 中进入标题、整备、完整人机战斗和结算，无控制台错误或失败请求；截图和事件记录在 `build/web-optimization/`。使用独立 `release-smoke` 浏览器存档，不访问生产在线身份。
- 对比数据：`build/web-optimization/comparison.json`。回归结果见同目录 `regression.log`。
- 源码规则身份仍由 `python3 tools/release_manifest.py --check` 校验。Web 生产在线模式的域名和 CORS 验收仍独立于本次减包。

复现构建：

```sh
python3 tools/build_web.py --stage /abs/new-web-runtime --output /abs/new-web
```

输出目录必须是新的。原始图片、声音、数据的 SHA 与缓存无损往返验证失败会终止构建。浏览器对战试玩应在每次发布前另行执行；构建成功不代替浏览器行为验收。
