# V2 本地包与发布流程

## 唯一试玩目录

`releases/V2/` 是本地最新完整候选版，只有一套，不按每轮开发序号累积。Mac 双击 `macOS/索拉里斯大乱斗.app`，或根目录 `START.command`。`EDITOR.command` 仅用于开发。

```text
releases/V2/
  先看这里.txt
  macOS/                 # APP 与对应 ZIP
  Windows/               # 完整游戏目录与对应 ZIP
  Web/                   # 网页部署文件与本机试玩脚本
  SolarisBrawl-V2-Web.zip
  SHA256SUMS.txt
  build-info.json
```

三端来自同一批源码与素材。Web 不是原生客户端，需要 HTTP 服务；不能双击 HTML 作为完整试玩。完整安装包不进入 Git。

## 构建与替换

运行 `python3 tools/build_local_release.py`，先在私有暂存目录完成三端导出、原始资源验证、Mac 签名验证、隐私检查和压缩。全部成功后才替换 `releases/V2`；失败保留上一份可玩包。结束后清除中间构建目录。小型日志与清单保留在忽略目录 `.local/release-audit/V2`。

本地候选标识为 `0.2.0`，序号 14105，桌面基线 `desktop-v142`。不修改源目录旧更新信任基线，不修改线上 feed，不自动推送。应用图标涉及项目与原生可执行文件，首次 V2 需要完整客户端包，不能将它伪装成旧基线的资源热补丁。

## 发布流程

GitHub 旧版统称为 V1，不重写旧 Git 标签与提交历史。V2 使用 `v0.2.0` 标签；旧下载入口可作为明确标注的兼容镜像替换为 V2。

V2 只维护本地最新目录。发布顺序：

1. 检查源码、素材与包内隐私，完成回归及平台验收。
2. 提交确切源码，以 GitHub 账号身份记录；为该提交创建 V2 的正式版本标签。
3. 将同一构建的 Windows、macOS、Web 三个 ZIP、校验和与说明上传至 GitHub Draft Release，确认附件后发布。
4. 同步国内下载与 Web 托管；完整包可下载并校验后，最后更新签名更新清单。保留旧 V1 的下载与更新兼容路径。

本地旧可执行包和临时导出可删除。线上仍在使用的更新协议基线只保留必要 PCK 和清单，存入 `.local/release-baselines/`，不作为试玩入口，也不上传为新版本。玩家存档、安装身份、凭据与现有源素材不属于可删除的构建缓存。

本轮 V2 新开局启用 `pocket_version=143`；已有局保留旧口袋规则。新规则有独立在线池，正式发布时须同步凭证服务白名单，不能混入 V1 池。发布时追加新池而保留旧池，不迁移旧局；新池真人不足时按原规则使用练习对手补位。
