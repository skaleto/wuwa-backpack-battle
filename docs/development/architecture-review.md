# 发布前结构审查（V138）

状态：迁移前的审查记录。目录调整已在本轮实施，最终结构与验证见 [结构说明](structure.md)。本轮不重写战斗继承算法。

## 结论

工程已能完整回归，但组织方式仍偏向迭代记录，而非维护中的产品。版本目录中确有现行资源；这说明当前文件留在旧位置，不代表这些目录名必须保留。历史兼容不能作为保留所有旧组织方式的理由。

本轮清理删除了 6,501 个已确认无用的文件（约 1.68 GiB）。清理后的独立目录通过 154/154 组游戏回归与 68/68 项服务端测试；这些结果证明本轮删除没有触发已有回归失败，不等于结构已经合理或完成所有视觉验收。

## 建议结构

不改变根目录的 Godot 工程入口，也不额外引入 app / domain / infrastructure 等整套抽象层。

```text
project.godot / main.tscn / README.md
scripts/
  game.gd                 # 场景装配与页面切换
  inventory/              # 占格、放置、背包、储物箱
  crafting/               # 配方、匹配、合成提交
  battle/                 # 当前模拟、事件、回放
  shop/                   # 经济与供给
  party/                  # 角色与招募
  ui/                     # 展示、交互与动效
  online/                 # 身份、匹配、快照传输
  storage/                # 本地持久化
  compat/                 # 明确版本范围的旧规则与迁移
assets/
  items/ characters/ ui/ vfx/ fonts/
  audio/music/ audio/sfx/
  generated/              # 运行需要的可重建轮廓等数据
  manifest.json           # 当前运行资源映射
data/
tests/
tools/
docs/
 services/pvp_signer/
```

- `data/`：当前目录 / 配方 / 商店规则；兼容快照放 `data/compat/`。先保持数据内容和规则摘要，再讨论拆分粒度。
- `tests/`：按功能与代码对应，另设 `fixtures/`、`visual/`、`compat/`；冻结输入不再寄放 docs。
- `tools/`：稳定的 `check.py`、`build.py` 入口；素材生成工具放 `tools/assets/`。版本号不再用于日常命令入口。
- `docs/`：现行设计、开发说明和发布说明；验收输出放忽略的 `build/qa/`，不与规则文档混放。
- 原图、许可和必要的可编辑源文件属于制作资料，不能简单判为无用。可保存在独立 `art_sources/`，明确不进游戏包；不复制多份已批准成品。

## 调整顺序与验收

1. **资源与文档归位**：建立旧路径到新路径的逐文件映射，按内容哈希验证不变；解析清单、动态路径、atlas 区域及音频分派。补齐生成工具路径。输出资源清单不得依赖“整个目录都打进去”。
2. **工具与测试入口归一**：保留全部有效测试与固定超时，显式注册；按功能移动用例及冻结数据。全新目录可以导入、运行、测试和构建，不依赖本机历史文件。
3. **代码按职责归组**：先移动已有模块，再单独处理入口过大、版本继承链和规则数据叠加。不要把文件迁移、数值变更和算法重写合为一次提交。

每阶段核对：素材原字节、完整性清单、轮廓缓存命中、固定密集战斗性能、154 组回归、服务端 68 项测试、旧存档与历史回放、在线池标识。只改目录不应要求玩家重开存档或改变匹配对象。

## 避免过度设计

- 每个资源有唯一现行位置，不长期保留新旧两份。
- 小功能不强行拆成多层；文件夹通常按功能分两层足够。
- 只有存在真实历史协议 / 存档差异时才保留版本边界。
- 不新增通用资源管理框架，不替换 Godot 自带的导入与加载机制。
- 重构前后都应能从 README 找到唯一的启动、测试和构建命令。
